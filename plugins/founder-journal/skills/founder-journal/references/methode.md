# Methode: Phasen, Gates, Schwellen

Quelle: Customer-First Playbook und Lösungskonzept (Repository `FounderJournal/docs/`).

## Die 5 Regeln

1. Erst Kunde, dann Code. Landingpage, Klick-Prototyp, Demo-Video und manueller Service sind erlaubt.
2. Eine Zielgruppe, ein Problem, ein Kanal.
3. Verhalten zählt, Meinung nicht. Geld, Zeit oder ein Intro sind ein Signal, „klingt spannend“ ist keins.
4. Zeitbox 6 Wochen pro Idee (nach Pivot 3 Wochen), dann Go/No-Go.
5. Täglich 60–90 Minuten Kundenkontakt, vor dem Bauen.

## Phasen

| Phase | Woche | Ergebnis |
| --- | --- | --- |
| 0 Triage | vor Woche 1 | ein Produkt gewählt, Rest eingefroren (nur bei mehreren Produkten) |
| 1 Problem & ICP | 1 | ICP-Satz, 3 Hypothesen mit Scoring, 1 gewählt |
| 2 Kanäle & Liste | 1–2 | 100 Kontakte mit Kanal und Aufhänger, 2 priorisierte Kanäle |
| 3 Problem-Interviews | 2–4 | 20 Gespräche ohne Pitch, Muster nach 10 |
| 4 Commitment | 4–6 | Zusagen auf der Commitment-Leiter |
| 5 Go/No-Go | Ende 6 | Entscheidung gegen die Schwellen |

## Gates

| Gate | Bedingung (aus Dateien prüfbar) | Danach erlaubt |
| --- | --- | --- |
| G0 Setup | ICP-Satz und Problem in `state.md` ausgefüllt | Landingpage bauen |
| G1 Landing live | Seite online, Landing-Review ohne offene Punkte | Outreach starten |
| G2 Erste Signale | ≥ 10 Interview-Dateien | Muster-Analyse, Commitment-Angebote |
| G3 Go | alle Go-Schwellen erfüllt | Produktcode für den Kern-Workflow |

## Go-Schwellen (bei Init festgeschrieben)

| Kriterium | Go | Pivot | Kill |
| --- | --- | --- | --- |
| Geführte Gespräche | ≥ 20 | ≥ 20 | < 10 trotz 100 Anfragen |
| Schmerz ≥ 4 von 5 | ≥ 60 % | 30–60 % | < 30 % |
| Aktiver Workaround mit Kosten | ≥ 50 % | 25–50 % | < 25 % |
| Zahlende Zusagen (Stufe 4–5) | ≥ 3 | 1–2 | 0 |
| Antwortrate auf Anfragen | ≥ 15 % | 5–15 % | < 5 % |
| Kanal skaliert (Kontakte/Woche ohne Netzwerk) | ≥ 20 | 5–20 | < 5 |

Änderung einer Schwelle nur mit Journal-Eintrag und Begründung, Abschnitt „Schwellen geändert“.

**Pivot:** genau eine Variable ändern (ICP, Problem oder Kanal), zurück auf G0, Zeitbox 3 Wochen. **Kill:** Idee beenden; bei mehreren Produkten das nächste aus `portfolio.md`. **Go:** nur den Kern-Workflow für die zahlenden Kunden bauen, Release in 2–4 Wochen.

## Commitment-Leiter

| Stufe | Signal |
| --- | --- |
| 0 | keins („klingt spannend“, Like, Klick) |
| 1 Zeit | Gespräch, zweites Gespräch, Demo, E-Mail-Adresse auf Warteliste |
| 2 Reputation | Intro zu Kollegen, Chef, anderen Eltern |
| 3 Daten/Aufwand | echte Daten oder Arbeitszeit für einen Pilot |
| 4 Geld (Absicht) | unterschriebener LOI mit Preis |
| 5 Geld (echt) | Vorauszahlung, bezahlter Pilot, Founding-Preis bezahlt |

## Wochenziele

50 Anfragen, 5–7 Gespräche, 3 Intros, ab Woche 4 ein Commitment ab Stufe 3.

## Problem-Scoring

Je Hypothese 1–5 Punkte für Häufigkeit, Schmerz, vorhandenes Budget, Erreichbarkeit. Unter 14 von 20: verwerfen oder zuspitzen. Punkte ohne Gespräche sind als „Einschätzung“ zu kennzeichnen.
